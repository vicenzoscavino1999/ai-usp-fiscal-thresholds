# Reproducing the Package

This guide defines the supported reviewer workflow for the public replication
package. The frozen methodological design is recorded in
`REPRODUCIBILITY_PLAN.md`, data redistribution decisions are documented in
`DATA_AVAILABILITY.md`, and release-level verification results are summarized in
`VALIDATION.md`.

## Reproduction Scope

| Path | Command | Included scope |
| --- | --- | --- |
| Public | `make reproduce-public` | Complete baseline, Monte Carlo, robustness, diagnostics, Phase B closure, H*, reference comparison, omega-I, LS-raw, CASEN and table-export verification |
| Full restricted run | `make reproduce` | Runs the public workflow and adds the ENAHO-based GMI-micro-PER verification when the non-redistributed required-variable extract is available |
| Restricted check after a public run | `make reproduce-restricted` | Verifies the ENAHO extension using the database and results already generated by `make reproduce-public` |

The public ZIP contains every redistributable input required by the public
command. ENAHO row-level microdata are not included; their provenance metadata,
retrieval script and aggregate registered outputs remain available.

## Canonical Reproduction

Requirements:

- Docker 27 or newer;
- approximately 8 GiB of available memory;
- approximately 40 minutes for a complete run, depending on hardware.

From the extracted ZIP root:

```powershell
docker build -t ai-usp-fiscal-thresholds .
docker run --rm `
  -v "${PWD}\data:/app/data" `
  -v "${PWD}\db:/app/db" `
  -v "${PWD}\results:/app/results" `
  -v "${PWD}\reports:/app/reports" `
  -v "${PWD}\figures:/app/figures" `
  ai-usp-fiscal-thresholds `
  sh -lc "make reproduce-public"
```

The Dockerfile uses `python:3.12.4-slim` pinned to digest
`sha256:a3e58f9399353be051735f09be0316bfdeab571a5c6a24fd78b92df85bcb2d85`.
Dependency installation is enforced with `pip install --require-hashes`.
The reproduction command does not contact external data providers.

`make reproduce-public` performs the following sequence:

1. verifies the pristine specification and protected-file freeze;
2. builds the database and official Tier A+B results from the bundled snapshot;
3. runs deterministic robustness and diagnostic specifications;
4. generates paper tables, figures and H* outputs;
5. compares 30 result files with the versioned reference;
6. verifies every public extension and table-export idempotence.

## Independent Verification Commands

After the canonical command completes, each contract can also be checked
separately:

```powershell
python reproducibility\verify_freeze.py
python reproducibility\verify.py
python reproducibility\verify_extensions.py
python -m pytest -q
```

| Command | Contract |
| --- | --- |
| `verify_freeze.py` | Primary specification hash, 16 protected files and amendment-chain coherence |
| `verify.py` | Schemas, canonical keys, missing/extra rows and 30 versioned reference files |
| `verify_extensions.py` | In-memory recomputation of public extensions and byte-idempotent LaTeX table export |
| `pytest` | Unit, regression, schema, determinism and packaging behavior |

The primary specification hash is
`0080d502a50db430998b56ebc6419ee181c90a1331cd2b650bb25db298523f81`.

## Verification Rules

- `verify.py` pairs rows by registered canonical keys before comparison.
- Tier A uses `atol=1e-10` and `rtol=1e-8`.
- Tier B probability comparisons use `atol=0.02` and `rtol=1e-8`.
- Tier C inputs use exact SHA-256 checks without numeric tolerance.
- Extension verification excludes only execution-provenance fields:
  `created_at*`, `build_id`, `runtime_seconds`, `commit_sha_at_run`,
  `git_dirty_at_run` and `download_date`.
- Stable nonnumeric values compare exactly; stable extension numerics use
  `atol=1e-10` and `rtol=1e-8`.
- Reexported publication tables must retain identical file hashes.

```powershell

```

## Running Without Docker

Docker is the reference environment. A Python 3.12 environment may run the
pipeline directly when GNU Make is available:

```powershell
pip install --require-hashes -r requirements-lock.txt
pip install --no-deps -e .
make reproduce-public
```

On Windows without GNU Make, use the direct commands listed in `README.md`.
Platform-local runs are useful confirmations; release verification uses the
digest-pinned container.

## Git Checkout Versus Public ZIP

A Git checkout intentionally omits runtime `data/`. The public ZIP adds the
curated baseline snapshot, extended WPP projection, UN SNA labor-share extract
and CASEN extract required by `make reproduce-public`. Reviewers starting from a
Git checkout must reconstruct or restore those inputs according to
`DATA_AVAILABILITY.md` before running the full pipeline.

## Release Bundle Verification

Release maintainers build and inspect the public archive with:

```powershell
make bundle-public
make verify-bundle
```

The bundle verifier checks the per-file manifest, path safety, symlinks,
executable payloads, primary-specification hash and declared release metadata.
The external SHA-256 distributed alongside the ZIP verifies the archive as a
whole.
